# Step QoR Analysis Metrics Extraction Design

## Goal

Make the normal ECC analysis phase the single producer of QoR data for every
completed flow step. Each step continues to write its legacy, step-named file
at `analysis/<step>_metrics.json` and, from the same in-memory metrics, writes
the existing normalized QoR artifacts:

- `analysis/qor_metrics.json`
- `analysis/qor_summary.json`
- `analysis/qor_hotspots.json`

No GUI code may read `feature/`, `output/`, `report/`, or log files directly.
There is no separate backfill command; a normal rerun of a step refreshes all
of its analysis files.

## Scope and data contract

`<step>` preserves the flow step name as constructed today, for example
`Floorplan_metrics.json`, `place_metrics.json`, `sta_metrics.json`, and
`Harden_metrics.json`. The legacy file remains a flat compatibility map. The
three normalized files retain their existing schema and are derived only from
that flat map, so the two representations cannot diverge.

An unavailable source must not be represented as a zero-valued metric. The
legacy field is omitted, and `qor_summary.json` reports the normalized metric
name in `missing_metrics`. A successful step can therefore have incomplete
QoR data without being misreported as a clean result.

## Source-to-metric mapping

| Step | Source inside its workspace directory | Metrics written to `<step>_metrics.json` |
| --- | --- | --- |
| Floorplan | `feature/*db.json` | die/core area, dimensions, utilization, IO pins, instances, nets. |
| fixFanout | `feature/*db.json` | common physical metrics and actual `Pins.max_fanout`; the configured max-fanout parameter is only a fallback. |
| place | `feature/*step.json`, `feature/*map.json` | placement overflow/bin data, HPWL/GRWL/FLUTE, and EGR/RUDY/LUT-RUDY congestion summaries. |
| CTS | `feature/*step.json` | buffer count/area, clock-path buffer limits, total/max clock wirelength, tree depth. |
| legalization | `feature/*step.json` when present | total legalization movement; it remains absent when the producer does not create that summary. |
| route | `feature/*db.json`, `feature/*step.json` | final wirelength/via count, layer-assignment demand/overflow, and the latest detailed-routing iteration's violation, patch, wirelength, and via totals. |
| drc | `feature/*step.json` | DRC violation count. |
| filler | `feature/*db.json` | post-fill physical scale metrics. |
| RCX | `output/` and configured SPEF paths | actual/expected/missing SPEF corner counts and DEF/GDS artifact presence. |
| sta | each configured `output/<liberty_corner>/<rcx_corner>/qor_summary.json` | worst setup/hold WNS/TNS, minimum achieved frequency, setup/hold violating path totals, actual/expected/missing corner counts, and worst-corner labels. |
| Harden | `output/` | GDS/LEF/LIB/LIB-check/preview presence and aggregate missing-artifact count. |

STA consumes only the structured `qor_summary.json` generated by iSTA. Old
text reports and legacy `*.rpt.json` files are not parsed. For the inspected
`ws_0006`, the historical STA run contains text reports only; a rerun with the
current iSTA build is required to populate `sta_metrics.json`.

## Execution flow

```text
completed step
  -> existing build_metrics_<step>() reads feature/output artifacts
  -> analysis/<step>_metrics.json
  -> normalized qor_metrics.json / qor_summary.json / qor_hotspots.json
  -> ECOS Studio reads analysis files only
```

The implementation stays in the existing ECC metrics builders. It must not
add a second parser or duplicate the source-selection rules in the desktop
application. Existing stage-specific report and checklist behavior remains
unchanged except that STA checklist and metrics share the structured summary
reader.

## Error handling

- Missing or malformed feature/output data is ignored safely; the builder still
  writes all metrics that can be supported by available inputs.
- RCX and Harden express artifact incompleteness as explicit numeric metrics.
- STA counts configured report locations, validates every JSON summary, and
  marks missing or invalid corners as incomplete. It never falls back to text
  parsing.
- Numeric parsing rejects non-finite values and preserves existing unit
  conversions, including database units to microns where already used.

## Verification

Add or retain focused ECC tests for all extended builders, including:

1. Place map, CTS step, route final-iteration, and absent legalization source.
2. RCX present/missing SPEF corners and final artifacts.
3. STA multi-corner aggregation, missing configured corners, and rejection of
   legacy report JSON.
4. Harden package completeness.
5. Generation of both the legacy step-named metrics file and all normalized
   QoR files from one builder call.

Run the ECC test module, relevant checklist tests, GUI QoR consumer tests, and
a full `make build`. Verify the resulting AppImage is executable and carries
the ECC binary containing the `qor_summary.json` support string.
